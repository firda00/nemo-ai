# Nemo: работа с Astra и Claude

Обновлено 6 сентября 2026 по запросу владельца проекта. Это текущие рабочие договорённости; исторические отчёты не переписываются.

## Как ставить задачу

Указывайте результат, пользователя, исходные материалы, ограничения и способ проверки. Небольшие уточнения можно присылать во время работы; они дополняют текущую задачу. Пример для Nemo:

> Доведи сценарий «загрузить выписку → выбрать день → получить проверяемые доходы и расходы» до локальной готовности. Пользователь — предприниматель в Узбекистане. Используй существующий код и стиль Nemo, RU/UZ/EN. Сохраняй связь каждой суммы с исходной строкой. Не вызывай live API, не коммить и не деплой. Рутинные решения принимай самостоятельно. Делегируй отдельную проверку Claude Fable 5.1, если доступен. Готовность: успешный сценарий, понятный отказ на неполном файле, изоляция пользователей, браузерная проверка и полный quality gate. Покажи изменённые файлы и оставшиеся ограничения.

## Организация работы

- Codex реализует текущий этап и отвечает за итог. Claude получает ограниченную независимую задачу: проверку финансовой логики, аудит лендинга или отдельный файл с явным владельцем.
- Один файл одновременно редактирует один исполнитель. Делегация содержит RECRUIT_REQUEST, ROLE, TASK, OWNED_PATHS, REASON, DONE_WHEN. Для проверки достаточно доступа на чтение.
- Не останавливать рутинную работу из-за старого требования «только Claude пишет код». При недоступном исполнителе фиксировать реальную ошибку и продолжать то, что доступно; не выдавать собственную проверку за независимую.
- Сообщения короткие, по-русски: что установлено, что исправлено, что ещё не проверено. Не считать зелёный mock-тест доказательством production-готовности.
- Для каждого завершённого этапа хранить результат, команды/коды выхода и хеши исходников. После исправлений запускать релевантные тесты; полный gate — перед завершением стабильного этапа.
- Действующие ограничения находятся в AGENTS.md. Для production release Nemo владелец отдельно разрешил деплой 6 сентября 2026; разрешение на Claude Code по-прежнему не разрешает платные API Nemo, отправку сообщений или коммит.

## Настройка под Astra

Задачи получают чёткие границы автономности, критерии готовности, правила делегации и проверки. Противоречащие им инструкции в AGENTS.md и CLAUDE.md согласованы. Для этой настройки не требуется менять модели приложения или глобальную конфигурацию Codex.

Официальное руководство рекомендует явные инструкции о продолжении работы, уточнениях, стиле, делегировании и соразмерном тестировании. Оно отдельно подчёркивает влияние конфликтующих skill/markdown-инструкций. [OpenAI: GPT-6 Astra](https://developers.openai.com/api/docs/guides/latest-model).

Codex читает проектные инструкции с учётом вложенности и override-файлов; после изменения они будут применяться в новых сессиях. [OpenAI: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

При будущей отдельной миграции API на Astra нужно проверить Responses tool calling и совместимость параметров. Это не выполненная миграция. Claude Fable 5.1 проверен по [странице Anthropic](https://www.anthropic.com/claude/fable); модель в задаче указывается явно, без подмены.

## Функциональность, лендинг и AGI

Ближайший продуктовый результат — работающие процессы с понятным входом и проверяемым выходом. На лендинге показывать реальные возможности, состояние закрытой беты и ограничения подключений. Не публиковать неподтверждённые цифры клиентов, работающих интеграций, экономии времени или обещания AGI.

Гипотеза отличия Nemo: повторяемые рабочие процессы, источники и расчёты, локальные языки/интеграции, разрешения и история выполнения. Её нужно проверить на пилотах с реальными клиентами: успешное завершение задачи, время до результата, повторное использование, число ручных исправлений и готовность платить. До таких пилотов превосходство над ChatGPT не доказано.

AGI — отдельное исследовательское направление после критериев Stage 1 из NEMO_AI_SPEC.md. Исследовательские демонстрации не смешиваются с обещаниями работающего продукта.
