# Медиа и управляемое улучшение агентов

## Что уже доступно

- анализ ссылок на видео/профили и отдельных кадров через vision;
- генерация изображений через подключённый провайдер;
- задания для видео/голоса/аватаров через реальные media jobs;
- библиотека результатов, где сохраняются запуски и созданные медиа;
- автопроверка результата командой reviewer до выдачи финального материала;
- импорт собственных skills и подключение HTTP/MCP-инструментов.

## Профессиональный media pipeline

Для каждого media-задания агент должен проходить одинаковый контролируемый цикл:

1. **Бриф:** цель, аудитория, платформа, формат, длительность, язык, брендовые ограничения.
2. **Исходники:** загрузка изображения, видео, аудио, PDF, текста или ссылки. Медиа хранится в tenant-scoped storage.
3. **Понимание:** транскрибация, OCR, scene/shot list, speaker labels, извлечение таймкодов и объектов.
4. **План:** storyboard, сценарий, монтажные точки, титры, voice-over, CTA и список отсутствующих исходников.
5. **Производство:** генерация или монтаж через подключённый executor с фиксированным лимитом тарифа.
6. **QC:** проверка длительности, разрешения, aspect ratio, громкости, субтитров, орфографии, брендовых правил и safety.
7. **Human review:** пользователь утверждает результат перед публикацией или отправкой в канал.
8. **Доставка:** экспорт, ссылка на результат, версия, хеш исходников и полный audit trail.

На первом production-пилоте нужно включить только один узкий сценарий: `video/audio → transcript + OCR → storyboard + captions → preview`. Полный автоматический монтаж и публикация подключаются после нагрузочного теста и проверки executor.

## Как агент улучшается

«Самообучение» в Nemo означает накопление проверяемых сигналов и создание версий, а не бесконтрольное переписывание системы.

- После каждого запуска сохраняются входной бриф, использованные источники, результат, reviewer score, ошибки и пользовательское решение.
- Агент предлагает небольшое изменение prompt/skill на основании повторяющейся проблемы.
- Независимый reviewer сравнивает текущую и новую версию по eval-набору.
- Изменение проходит sandbox/shadow run и получает score, changelog и владельца.
- В production автоматически разрешены только prompt-only изменения с высоким score, cooldown и лимитом частоты.
- Инструменты, permissions, billing, секреты, код, deployment и системные safety-правила не меняются автоматически.
- Любая версия имеет rollback и остаётся видимой в истории агента.

## Контур обратной связи для медиа

Для каждого результата фиксируются:

```text
brief → source manifest → model/provider → generated asset
      → technical QC → reviewer score → human decision
      → error tags → next skill/prompt proposal
```

Примеры error tags: `wrong_aspect_ratio`, `missing_caption`, `ocr_error`, `unsupported_claim`, `brand_tone`, `audio_clipping`, `weak_hook`, `wrong_language`.

## Границы безопасности

- Агент не публикует медиа без явно включённого канала и approval policy.
- Файлы и внешние инструкции считаются недоверенными данными и не исполняются.
- Отдельные аккаунты не видят чужие исходники, embeddings, результаты или feedback.
- Любой новый media executor проходит contract test, live smoke, quota test и rollback test.
- Для обучения используются минимально необходимые данные; чувствительные материалы должны быть обезличены.
