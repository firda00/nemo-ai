# OpenMontage: исследование для Nemo AI

Дата проверки: 2026-07-22.

## Вывод

OpenMontage не интегрируется в production Nemo AI на этом этапе. Репозиторий распространяется по GNU AGPLv3, поэтому сетевой доступ к изменённой версии может потребовать предложения соответствующего исходного кода пользователям сервиса. До письменного заключения юриста нельзя встраивать или модифицировать OpenMontage внутри закрытого backend-кода Nemo AI.

Это исследовательское решение, а не юридическая консультация.

## Что подтверждено

- Официальный репозиторий: https://github.com/calesthio/OpenMontage
- Лицензия репозитория: GNU AGPLv3.
- Базовые зависимости: Python 3.10+, FFmpeg и Node.js 18+; часть сценариев использует Remotion, HyperFrames и внешних AI-провайдеров.
- Проект рассчитан на агентный производственный процесс с согласованием творческих решений, а не на готовый multi-tenant SaaS API.

## Лицензионный риск

Раздел 13 AGPLv3 относится к удалённому взаимодействию по сети. GNU FAQ отдельно поясняет, что программа под AGPLv3 должна предлагать исходный код пользователям, которые взаимодействуют с ней удалённо. Граница производного произведения, взаимодействия отдельных процессов и обязанностей для конкретной архитектуры зависит от реализации и должна быть проверена юристом.

## Допустимый следующий шаг

1. Только изолированный внутренний proof-of-concept без клиентского доступа и без копирования кода OpenMontage в основной backend.
2. Не изменять upstream-код до определения процесса публикации Corresponding Source и notices.
3. Держать процесс/контейнер и хранилище артефактов отдельно; общаться через узкий документированный протокол. Это уменьшает связанность, но само по себе не гарантирует отсутствие AGPL-обязательств.
4. Перед любым публичным пилотом получить письменное лицензионное заключение и определить: состав публикуемого исходного кода, место выдачи исходников, notices, версии зависимостей и процесс обновления.
5. После юридического допуска провести технический smoke на отдельном Linux worker: FFmpeg/ffprobe, Node/Remotion, Python, лимиты CPU/RAM/диска, таймауты, отмена задач и очистка временных файлов.

## Чего не делать

- Не импортировать OpenMontage как библиотеку в Supabase Edge Functions или основной proprietary backend.
- Не давать клиентам обещание работающего видеомонтажа до реального executor и end-to-end smoke.
- Не считать отдельный контейнер автоматическим освобождением от AGPL.
- Не использовать CL4R1T4S.

## Критерий пересмотра

Решение можно пересмотреть только когда одновременно есть юридическое заключение, воспроизводимый Linux worker, изоляция tenant-данных, конкретные лимиты заданий и успешный end-to-end smoke с очищенными тестовыми данными.
