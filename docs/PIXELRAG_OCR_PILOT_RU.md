# PixelRAG/OCR: защищённый пилот

Дата решения: 2026-07-22. Статус: control-plane реализован локально, feature flag выключен; production-ready статус не заявляется.

## Техническое решение

- PixelRAG рассматривается как Apache-2.0 worker для визуальных embeddings страниц и изображений.
- Векторное хранилище: Qdrant. Каждый point обязан содержать `account_id` в payload, каждый поиск обязан включать фильтр по тому же `account_id`.
- Unlimited-OCR имеет MIT-лицензию, но его рабочий путь требует NVIDIA/CUDA и отдельного GPU worker.
- Supabase хранит только задания, статусы и извлечённый текст. Клиент не может напрямую менять эти таблицы.

## Конкретные лимиты пилота

- максимум 20 МБ на исходный файл;
- максимум 200 страниц на задание;
- максимум 2 задания со статусом `queued` или `processing` на аккаунт;
- максимум 1000 заявленных страниц за скользящие 24 часа на аккаунт;
- максимум 30 отправок за скользящую минуту на аккаунт.

Проверки лимитов сериализуются advisory transaction lock по аккаунту. Путь файла обязан начинаться с `<account_id>/visual-rag/`; абсолютные пути, `..`, обратные слеши и пустой хвост запрещены.

## Изоляция данных

- RLS разрешает участнику только чтение строк своего аккаунта.
- Клиентские INSERT/UPDATE/DELETE отозваны; submit/status доступны через account-scoped RPC.
- Account ID выводится сервером из аутентифицированного пользователя и не принимается из тела запроса.
- Worker claim/finalize доступны только роли `service_role`; claim использует `FOR UPDATE SKIP LOCKED`.
- Составной внешний ключ `(job_id, account_id)` запрещает worker записать страницу в чужой аккаунт.

## Feature flag и честное поведение

Пилот по умолчанию выключен через `app.visual_rag_enabled`. Пока значение не равно `on`, submit возвращает `feature_disabled`/HTTP 503. Edge Function не выполняет и не имитирует OCR.

## Проверки

`npm run test:visual-rag` выполняет детерминированный контракт: границы всех лимитов, ровно два конкурентно допустимых задания, отказ третьему, межтенантный отказ, path traversal, права worker и account-фильтр Qdrant. Live-режим включается только явно через `VISUAL_RAG_LIVE=1` и отдельные тестовые credentials.

## Текущий блокер

На текущем Windows-хосте нет NVIDIA/CUDA, Docker, FFmpeg и пригодного Python runtime. Поэтому реальный GPU OCR, построение embeddings, Qdrant-нагрузка и end-to-end worker smoke не пройдены. До отдельного Linux/GPU worker, очистки тестовых данных и замеров latency/VRAM/стоимости функцию нельзя включать для клиентов.
