# ИИ-сотрудники Nemo

Каталог `/app/employees` создаёт сохраняемый черновик сотрудника из задачи владельца, контекста компании, языка и выбранной модели. Название профессии задаёт инструкции и ограничения; оно само по себе не подключает CRM, телефонию, почту или платёжные системы.

| Специализация | Начальный результат |
| --- | --- |
| Колл-центр и поддержка | Ответы по базе знаний, квалификация обращения, передача оператору |
| Финансы | Расчёты и объяснения по предоставленным данным, проекты финансовых отчётов |
| Маркетинг | Позиционирование, брифы и тексты кампаний |
| SEO | Аудит предоставленных страниц, семантика и план улучшений |
| Инженерия | Анализ требований, код и план проверки |
| Руководитель / CEO | Сводка, варианты решений, приоритеты и поручения |
| Продажи | Квалификация лида, проект предложения, следующий шаг |
| HR | Критерии вакансии, вопросы для интервью, проекты кадровых материалов |
| Операции | Регламенты, контрольные списки и разбор процессов |
| Анализ данных | Проверяемые расчёты, выводы и ограничения данных |
| Своя роль | Инструкции для другой сферы без фиктивных подключений |

Черновик нужно настроить и проверить в карточке сотрудника. Публикация остаётся отдельным серверным переходом после оценки. Финансовые, кадровые и произвольные роли получают усиленный уровень защиты. Роль колл-центра не означает готовую исходящую телефонию.

## Управление работой

- Диалоги и передача оператору: `/app/dialogues`.
- Запросы на решение владельца: `/app/approvals`.
- Политика `read_only` запрещает внешние изменения. Политика `approval_required` создаёт запрос на согласование для действий, которые могут менять внешнее состояние.
- Согласование сохраняет решение. Универсальный исполнитель одобренных действий ещё не подключён; интерфейс не сообщает о выполнении по одному факту одобрения.
- Клиент сохраняет только подтверждённую сервером запись. Повтор неизменённого черновика использует тот же UUID; смена аккаунта отменяет применение позднего ответа.

Для полезного первого запуска задайте: конкретный результат, исходные материалы, ограничения, доступные инструменты и критерий готовности. Пример: «Подготовь финансовый отчёт за август из приложенного XLSX. Покажи формулы, пропуски и расхождения. Не придумывай недостающие значения. Результат — таблица расчётов и PDF для проверки владельцем».

## Модели и доступность

Каталог сотрудников использует существующий маршрутизатор моделей Nemo. Отдельный прямой чат GPT-6 Astra / Claude Fable 5.1 и его подключение ключей описаны в `MODEL_CAPABILITIES.md`; наличие этого чата не означает, что все инструменты этих продуктов уже доступны каждому сотруднику.

Документы требуют серверных таблиц, scoped Edge API и работающего document worker. Напоминания требуют отдельного включения планировщика и подтверждённого получателя. Источники, API и каналы отмечаются как доступные только после реального подключения. Последний факт публикации и эксплуатационные ограничения фиксируются в отчёте выпуска, а локальные тесты не заменяют такую проверку.
