# Nemo: GPT-6 Astra и Claude Fable 5.1

Требование владельца от 6 сентября 2026: платформа должна постепенно предоставлять все доступные через API возможности этих моделей и необходимые инструменты выполнения. Это цель разработки, а не утверждение о достигнутом полном соответствии ChatGPT или Claude Code.

## Реализуемое подключение

Прямой чат использует точные модели `gpt-6-astra` и `claude-fable-5-1`, выбранного провайдера и его ключ пользователя. Быстрый существующий режим остаётся отдельным выбором. При отсутствии ключа или ошибке выбранная модель не заменяется автоматически. Выбор глубины рассуждения начинает новый контекст. История в интерфейсе ограничена текущей сессией; сервер выдаёт зашифрованное продолжение с привязкой к пользователю, аккаунту, провайдеру, модели и глубине.

OpenAI рекомендует Astra для сложных задач, кода, исследований и документов; для инструментов используется Responses API. Fable 5.1 работает через Messages API и требует сохранения нативных блоков истории. Основание: [OpenAI — модель](https://developers.openai.com/api/docs/models/gpt-6-astra), [руководство Astra](https://developers.openai.com/api/docs/guides/latest-model), [Anthropic — Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/overview).

## Матрица текущего этапа

| Возможность | Что подключено в коде Nemo | Что ещё требуется |
| --- | --- | --- |
| Текст, объяснения, перевод, код как текст | Прямой выбор обеих моделей, глубина, история | Проверка реальными моделями после отдельного разрешения |
| Анализ изображений | До двух inline-изображений в прямом чате | Большие файлы и provider Files API |
| Вызов функций | Backend выдаёт вызовы и принимает полный набор результатов с сохранением нативной истории | Подключить разрешённые исполнители Nemo к этому циклу; UI пока отправляет tools:[] |
| Документы и таблицы | Существуют отдельные проверенные сценарии генерации и расчётов | Передавать выбор новой модели в каждый совместимый сценарий |
| Поиск и браузер | Существуют отдельные подключения и маршруты | Связать их с новой моделью, проверить разрешения и восстановление |
| Выполнение кода, shell, computer use | Отдельные компоненты платформы | Подключение к новой модели, изоляция среды, подтверждение внешних действий |
| Аудио, видео, генерация изображений | Отдельные медиа-сценарии | Совместимые специализированные модели/инструменты; сам текстовый ID их не включает |
| Долгие задачи и потоковый ответ | Ограниченные ожидания, остановка клиентского ожидания, отдельные worker-процессы | Streaming, async continuation, compaction и полный жизненный цикл native tools |

Это описание кода. Итоговые команды и коды выхода сохраняются в `agent-hub/artifacts/auth-latency-stage/implementation-verification.json`. Исторический auth-latency этап не включал live API, production Supabase, коммит или деплой; текущий production release зафиксирован ниже отдельно.

## Скорость и критерии готовности

Объяснительные вопросы без файлов и действий идут в прямой чат. Исполнение явно заданных задач сохраняет прежние сценарии. В общей цепочке legacy-моделей очередь, сеть, чтение и повторы ограничены одним бюджетом 45 секунд. Это устранение лишнего ожидания, а не обещание скорости реального провайдера.

Для каждой следующей возможности нужны: доступный пользователю вход, настоящий исполнитель, разрешения, результат с доказательствами, отмена/восстановление, независимая проверка и измеренная задержка. Карточка функции или название модели сами по себе критерием готовности не являются.

## Production release update

6 сентября 2026 опубликованы выбранные маршруты `cli-chat`, `agent-tool`, `test-agent`, `compose-agent`, `agent-evals`, `approval-queue`, документные, финансовые, marketing и owner workflow функции. Их production auth-границы проверены без вызова модели. Это не означает, что каждый инструмент этих моделей подключён к каждому сотруднику: для каждого действия по-прежнему нужны собственный исполнитель Nemo, разрешение и проверяемый результат.
